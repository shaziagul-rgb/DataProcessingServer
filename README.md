
# DataProcessingServer

Node.js server for processing augmented reality (AR) camera data and interfacing with a Linux-based deep-learning camera pose estimation pipeline.

## Overview

**ProcessingServer** provides the communication and processing layer between the Mobile/Unity C# AR application and the deep‑learning–based pose‑estimation pipeline running in a Linux environment. It manages image transmission, preprocessing, model inference, pose post‑processing, and returns the final 6‑DoF camera pose to the mobile client for AR rendering and evaluation.

The server receives camera images and camera calibration information from the mobile application, stores and prepares the data on the Linux system, starts the required pose estimation processing through external batch scripts, retrieves the resulting camera pose data, and sends the results back to the mobile client.

## System Architecture

```text
Unity / C# AR Application
          |
          | Camera image
          | Camera calibration
          v
   DataProcessingServer
       (Node.js)
          |
          | Store and prepare data
          v
 Pose Estimation Pipeline
       |         |
      Deep Learning
       |         |
       +----+----+
            |
            | Estimated camera pose
            v
   DataProcessingServer
          |
          | Pose data
          
Unity / C# AR Application
```

## Main Responsibilities

DataProcessingServer is responsible for:

* Receiving camera images — Processes incoming frames sent from the Unity application.
* Receiving camera calibration information — Stores intrinsic camera parameters required for pose estimation.
* Managing image, calibration, and pose data — Organises all session‑related data for processing and logging.
* Creating dataset directories — Generates per‑user and per‑session folders for dataset storage.
* Starting external pose‑estimation scripts — Launches deep‑learning inference modules (e.g., ESAC/ACE).
* Interfacing with Linux‑based batch scripts — Communicates with GPU‑enabled pipelines through batch‑script execution.
* Reading resulting camera pose data — Parses pose output files generated by the deep‑learning pipeline.
* Returning pose information to Unity — Sends the final 6‑DoF pose back to the Unity application.
* Recording image upload and processing times

## Processing Workflow

The typical workflow is:

1. The Unity/C# application captures an image using the mobile device camera.
2. The image and camera calibration information are sent to DataProcessingServer.
3. The server stores the image and associated information on the Linux system.
4. The server starts the required pose estimation pipeline using an external script.
5. The deep-learning pipeline processes the image and estimates the camera pose.
6. The resulting pose data is written to an output file.
7. DataProcessingServer reads the pose corresponding to the processed image.
8. The pose data is returned to the Unity/C# application.
9. Processing times can be recorded for performance evaluation.

## Installation

Clone the repository:

```bash
git clone 
cd DataProcessingServer
```

Install the Node.js dependencies:

```bash
npm install
```

## Configuration

The server uses configuration values for paths that depend on the local Linux environment.

For example:

```text
PORT=3001
DATA_ROOT=/path/to/data
SCRIPT_DIR=/path/to/scripts
ESAC_SCRIPT=/path/to/ARscript.sh
ACE_SCRIPT=/path/to/fbs.sh
CALIBRATION_FILE=/path/to/MobCalib.txt
```

Create a local configuration based on `.env.example`.

Do not commit machine-specific paths, private configuration, or personal calibration data to the repository.

## Running the Server

Start the server with:

```bash
node server.js
```

The default port is:

```text
3001
```

The server can then be accessed locally at:

```text
http://localhost:3001
```

## API Endpoints

### Check Connection

```text
GET /checkConnection
```

Checks whether the server is running and accessible.

### Health Check

```text
GET /health
```

Returns the current server status.

### Create Folders

```text
POST /createfolder
```

Creates the required directories for a user/session.

### Send Phone Model

```text
POST /send-PhoneModel
```

Receives a mobile phone model and returns the corresponding camera calibration information.

### Send User Information

```text
POST /send-User
```

Receives the user/session ID and mobile device model and prepares the required directories and calibration information.

### Upload Image

```text
POST /upload-image
```

Receives:

* Camera image
* User/session ID
* Mobile device model
* Camera calibration
* Image name

The image and associated data are stored on the Linux server.

### Run Deep learning Processing

```text
POST /runBatchFile
```

Starts the configured ESAC processing pipeline for the specified user/session.

After processing is completed, the server reads the pose corresponding to the requested image and returns the pose data to the Unity client.

### Run ACE Processing

```text
POST /runAceBatchFile
```

Starts the configured ACE processing pipeline and returns the corresponding pose information.

### Read Pose Data

```text
GET /readPosesfile
```

Reads pose information generated by the pose estimation pipeline.

## Performance Measurement

The server records processing times associated with the image processing workflow.

The measurements include:

* Image upload time
* Pose estimation processing time
* Total processing time

These measurements can be used to evaluate the performance of the AR processing pipeline in research experiments.

## Research Context

DataProcessingServer was developed as part of research into large-scale outdoor augmented reality and camera pose estimation.

The server provides the infrastructure required to connect a mobile AR application with server-side deep-learning pose estimation methods.

The separation between the Unity client, Node.js server, and Linux-based pose estimation pipeline allows different pose estimation methods to be evaluated without requiring the complete deep-learning system to run directly on the mobile device.

## Related Components

This repository contains the server-side communication and processing component.

The deep-learning pose estimation methods and other research components may be maintained in separate repositories.
